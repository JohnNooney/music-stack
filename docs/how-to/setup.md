# How to set up the stack

From a fresh clone of this repo to a running stack: Deemix downloads, the
Lidarr stack downloads, `union_library` merges both into the union root, and
Jellyfin serves it. The `library-watcher` service then keeps the union and
playlists current on its own (ADR 0005). Run every command from the repo root
(`/Users/john/Docker/jellyfin`). Do the steps **in order** — later steps need
keys generated by earlier ones.

On this machine everything below is already done; the runbook is for a fresh
clone or a rebuild. Steps marked *(this machine: already set)* can be skipped
here.

## Steps

1. **Prerequisites.** Docker Desktop running. Know your uid/gid (`id -u` /
   `id -g`) and pick `DATA_DIR` — the root of the Lidarr-stack data layout
   (this machine: `/Users/john/Music/Lidarr`). The source trees the union
   library links into must exist: `mkdir -p ~/Music/Deemix ~/Music/Lidarr
   ~/Music/Jellyfin`.

2. **`.env`.** `cp .env.example .env` and fill in:
   - `JELLYFIN_*` — leave `JELLYFIN_API_KEY` empty for now (created in step 7).
   - `DATA_DIR`, `PUID`, `PGID`, `TZ` — for the Lidarr stack.
   - `SLSKD_SLSK_USERNAME`/`SLSKD_SLSK_PASSWORD` — Soulseek account.
   - `SLSKD_USERNAME`/`SLSKD_PASSWORD` — slskd web UI login.
   - `SLSKD_API_KEY` — invent one (16–255 chars). Soularr reuses it in step 8.
   - Watcher knobs are optional — `WATCH_INTERVAL_S`, `QUIET_PERIOD_S`,
     `RETRY_COOLDOWN_S`, `MIGRATE_MODE`, `IMPORT_MODE` all have compose
     defaults; add them to `.env` only to override.

3. **Seed the app configs** *(this machine: already set — the real dirs are
   git-ignored and were never committed)*. On a fresh clone the dirs don't
   exist, so create them and copy the templates:
   ```bash
   mkdir -p soularr slskd lidarr prowlarr transmission
   cp soularr/config.ini.example soularr/config.ini
   cp slskd/slskd.yml.example slskd/slskd.yml
   ```
   In `soularr/config.ini`, set `[Slskd] api_key` = your `SLSKD_API_KEY` now;
   `[Lidarr] api_key` comes in step 8.

4. **`DATA_DIR` layout.** Docker creates missing folders on `up`, or:
   ```bash
   mkdir -p "$DATA_DIR"/{media/music,slskd/{downloads,incomplete},torrents/{music,incomplete,torrent-files}}
   ```

5. **Start everything:**
   ```bash
   docker compose up -d
   ```
   Soularr will complain until `config.ini` has the Lidarr key — fixed in
   step 8. slskd should show *Connected* to `vps.slsknet.org` in its web UI
   (http://localhost:5030) since its credentials came from `.env`.
   `library-watcher` builds from `docker/library-watcher/` on first `up` and
   immediately runs one `migrate` + `union_library` pass (see `docker logs
   library-watcher`), so the union root may already exist by step 7.

6. **Wire the Lidarr stack** — follow
   [wire-lidarr-stack.md](wire-lidarr-stack.md):
   - Lidarr: root folder `/data/media/music`, copy the API key (Settings →
     General), add Transmission as download client, widen Metadata Profiles.
   - Prowlarr: add indexers, then Settings → Apps → Lidarr with that API key.
   - Transmission: stop, edit `transmission/settings.json` (download/incomplete/
     watch dirs), start. *(this machine: already applied.)*
   - Slskd: shares/limits are already in `slskd.yml` (seeded in step 3);
     just confirm it is connected.

7. **Jellyfin** (http://localhost:8096): first-run wizard → add a Music
   library pointed at `/media` (the union root) → Dashboard → API Keys → +
   → put the key in `.env` as `JELLYFIN_API_KEY`, then recreate the watcher so
   it picks the key up — `docker compose up -d library-watcher` (`restart`
   keeps the old env; `import` and the refresh nudge need the key). Build the
   union root first so the scan sees content:
   ```bash
   python3 -m union_library --dry-run
   python3 -m union_library
   ```

8. **Soularr.** Put the Lidarr API key from step 6 into
   `soularr/config.ini` `[Lidarr] api_key`, then `docker compose restart
   soularr`. `docker logs soularr` should show poll cycles, not 401s.

9. **Deemix** (http://localhost:6595): log in (Deezer ARL — saved to the
   git-ignored `deemix-config/login.json`). The tracked `config.json` already
   carries the required structure-playlist settings; don't change them (see
   [settings.md](../reference/settings.md)).

10. **Smoke test.** Add one small artist in Lidarr, watch it flow through
    Soularr/slskd → `/data/media/music` → union root → Jellyfin (`docker logs
    library-watcher` shows the poll → quiet period → `union_library` run).
    Then a Deemix download: the watcher imports the `.m3u8` itself — or force
    it with `python3 -m reorganize_playlists import`.

## Done checklist

- [ ] `docker compose ps` shows all 9 services running.
- [ ] `docker logs library-watcher` shows its startup `migrate` + `union_library` run and polls, not errors.
- [ ] slskd web UI: *Connected* to `vps.slsknet.org`; shares list `/data/music` and `/deemix`.
- [ ] `docker logs soularr` shows poll cycles (grabs or "nothing wanted"), not 401/403.
- [ ] Lidarr sees `/data/media/music` as a root folder; test artist goes *wanted*.
- [ ] `python3 -m union_library --dry-run` plans links from both source trees.
- [ ] Jellyfin Music library scans `/media` and shows both Deemix and Lidarr content.
- [ ] `python3 -m reorganize_playlists import --dry-run` runs (needs `JELLYFIN_API_KEY`).
- [ ] `git status` shows no new tracked files under `lidarr/`, `prowlarr/`, `slskd/`, `soularr/`, `transmission/`, and `.env` is untracked.

## Notes

- Secrets never live in tracked files. `.env` and the app config dirs are
  git-ignored; only `*.example` templates are tracked. Full layout:
  [lidarr-stack.md § Secrets](../reference/lidarr-stack.md#secrets-layout).
- The arr services run as `${PUID}:${PGID}` (501:20 here);
  `jellyfin`/`deemix`/`library-watcher` stay on `501:501` — that difference is
  intentional.
- Per-service detail: [wire-lidarr-stack.md](wire-lidarr-stack.md).
  Troubleshooting ("what failure looks like"): [add-music.md](add-music.md).
  The VPN / port-forwarding caveat and other service notes:
  [lidarr-stack.md](../reference/lidarr-stack.md).
