# Why Jellyfin attributes an entire `Playlists/` folder to a single album/artist

> **Decisions taken from this research:** see the ADRs in [`docs/adr/`](adr/). The `.ignore` fix
> recommended in §10 was **rejected** because it hides the songs. Instead, songs moved into album folders
> and Jellyfin owns the playlists ([ADR 0001](adr/0001-songs-in-album-folders-jellyfin-owns-playlists.md)),
> at their exact Deemix paths ([ADR 0002](adr/0002-deemix-structure-playlist-mode-and-exact-deemix-paths.md)),
> backed up by an APFS clone and a text-only git repo ([ADR 0003](adr/0003-no-git-for-audio-apfs-clone-and-text-only-git.md)).

Research date: 2026-11 (Jellyfin server **10.11.11** on the user's instance at research time; server source inspected at
`jellyfin/jellyfin` master commit [`797999f`](https://github.com/jellyfin/jellyfin/tree/797999fc9bd49a9f0853916e2933e3ad06173503)).
**Verified against v12.4** (the instance was upgraded to 12.4.0 on 2026-11-10): `MusicAlbumResolver`,
`MusicArtistResolver`, `AlbumMetadataService.UpdateMetadataFromChildren`, and `DotIgnoreIgnoreRule`
are functionally identical at tag [`v12.4`](https://github.com/jellyfin/jellyfin/tree/v12.4) — same
folder→album/artist resolution, first-child `ALBUM` naming, union-of-artists assignment, and empty/non-empty
`.ignore` semantics. All findings and fixes below apply.

> **TL;DR — this is folder grouping, not tag handling.** In a Jellyfin *music* library, **any directory
> that directly contains audio files is imported as a `MusicAlbum` item**, and any directory that contains
> album-like subdirectories becomes a `MusicArtist`. The per-folder album is then *named after the first
> track's `ALBUM` tag* and assigned *the union of all child tracks' album-artist tags* (majority first).
> `Playlists/Bussin/` is therefore one album containing 133 tracks by ~33 different album artists, and
> `Playlists/` itself becomes an artist named "Playlists" containing all 37 playlist "albums".
> With the MusicBrainz fetcher enabled (it is, in this library), the pseudo-album is also identified as the
> *real* release matching the first track's album name — locking in the misattribution.

---

## 1. Symptom summary

- Every folder under `Playlists/` shows up in Jellyfin as **one album**, named after a seemingly random
  album (in reality: the first scanned track's `ALBUM` tag).
- Browsing an artist page pulls in an album that contains **other artists' songs** — the whole playlist
  folder rides along.
- A stray artist entry named **"Playlists"** may also appear (see §4).
- Embedded file tags are correct — verified locally (see §3).

## 3. Q1 — How a track's Album and (Album)Artist are determined

Jellyfin probes each audio file with **ffprobe** (format/streams) and reads tags with the **ATL**
library (`Track` class; TagLib# was replaced in 10.9):

- `MediaBrowser.Providers/MediaInfo/AudioFileProber.cs`
  ([L60-75](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L60-L75)):
  `new Track(audio.Path)`, `ATL.Settings.DisplayValueSeparator = '\u001F'` (unit-separator used to join
  multi-value tags), `ATL.Settings.UseFileNameWhenNoTitle = false`.
- Tag → field mapping
  ([L189-199](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L189-L199)):
  `trackTitle = track.Title ?? mediaInfo.Name` (ffprobe/filename fallback), `trackAlbum = track.Album ?? mediaInfo.Album`,
  `trackAlbumArtist = track.AlbumArtist`, `trackArist = track.Artist`. Sanitised by truncating at NUL.
- Stored onto the item:
  `audio.Album ??= trackAlbum` / `audio.Album = trackAlbum` on full replace
  ([L377-385](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L377-L385));
  `audio.Artists = performers`, `audio.AlbumArtists = albumArtists` only when `ReplaceAllMetadata` or the
  fields are empty
  ([L342-367](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L342-L367)).
  **Important:** an ordinary rescan does *not* overwrite previously-imported `Album`/`Artists`/`AlbumArtists`.
- If `ALBUMARTIST` is absent, **`albumArtists` falls back to the track artists**
  ([L354-356](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L354-L356)).
- Optional `PreferNonstandardArtistsTag` reads the multi-artist `ARTISTS`/`ALBUMARTISTS` fields instead
  ([L207-214, 227-234](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L207-L234)).
- The same names are also written into the `People` table with roles `Artist`/`AlbumArtist`/`Composer`
  ([L287-335](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L287-L335)
  — `_libraryManager.UpdatePeople(audio, people)`).
- MusicBrainz IDs are read from tags `MUSICBRAINZ_ARTISTID`, `MUSICBRAINZ_ALBUMARTISTID`,
  `MUSICBRAINZ_ALBUMID`, `MUSICBRAINZ_RELEASEGROUPID`, `MUSICBRAINZ_TRACKID`
  ([L486-540](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L486-L540)).

So the **per-track** `Album`/`Artists`/`AlbumArtists` come from embedded tags when present (filename only
as a title fallback). The user's symptom is therefore *not* tag parsing — it's what happens next, at the
folder level.

## 4. Q2 — How Jellyfin groups tracks into "albums" (the root cause)

Jellyfin does **not** group albums by `(album name, album artist)` tag key. In a music library the
album entity is decided **purely by directory**, during file resolution:

- **`MusicAlbumResolver`**
  ([`Emby.Server.Implementations/Library/Resolvers/Audio/MusicAlbumResolver.cs`](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Library/Resolvers/Audio/MusicAlbumResolver.cs)):
  - `Resolve` ([L57-82](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Library/Resolvers/Audio/MusicAlbumResolver.cs#L57-L82)):
    in a `CollectionType.music` library, a **directory** that is not inside another `MusicAlbum` and whose
    parent is not the physical root becomes a `MusicAlbum` **iff `ContainsMusic(children)`**.
  - `ContainsMusic` ([L125-180](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Library/Resolvers/Audio/MusicAlbumResolver.cs#L125-L180)):
    true when the folder has ≥1 direct audio file, *or* when all of its music-bearing subfolders are
    multi-disc folders (`AlbumParser.IsMultiPart`). If any subfolder contains music and is **not** a
    disc folder, the folder is *not* an album (`state.Stop()` at L168) — it can instead be an artist.
- **`MusicArtistResolver`**
  ([`MusicArtistResolver.cs`](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Library/Resolvers/Audio/MusicArtistResolver.cs)):
  a directory (parent not physical root, not inside an artist/album) that **contains a `MusicAlbum`
  subfolder** becomes a `MusicArtist`
  ([L112-119](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Library/Resolvers/Audio/MusicArtistResolver.cs#L112-L119));
  `artist.nfo` also forces it (L78-81). Resolver priorities: artist = `Second`, album = `Third`
  ([L43-48](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Library/Resolvers/Audio/MusicArtistResolver.cs#L43-L48)),
  so `Playlists/` is classified as artist *before* it can fall through to album/folder.
- **Physical root:** `GenericFolderResolver` marks the top media folder `IsRoot = (args.Parent is null)`
  ([`GenericFolderResolver.cs` L25](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Library/Resolvers/GenericFolderResolver.cs#L25));
  `args.Parent.IsRoot` prevents the collection root itself from being called an album/artist, not its
  children — so **level-1 folders are fair game for albums** (consistent with the docs' `Music/Album X/`
  example).

**Applied to `/media`:**

| Path | Resolves to | Why |
|---|---|---|
| `/media/Artist - Album/` | `MusicAlbum` | dir directly under the collection root containing audio files |
| `/media/Playlists/` | **`MusicArtist` named "Playlists"** | dir whose subdirs are all `MusicAlbum`s |
| `/media/Playlists/Bussin/` | **`MusicAlbum`** | dir containing audio files |
| `/media/Bussin.m3u` | `Playlist` | m3u in a music collection (see §6) |
| `/media/A$AP Ferg - Work.flac` | `Audio` | loose file (`AudioResolver` L78-130) |
| `/media/Config/` | `Folder` | no audio content |

Then `AlbumMetadataService.UpdateMetadataFromChildren`
([`AlbumMetadataService.cs` L71-103](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/Music/AlbumMetadataService.cs#L71-L103))
post-processes each `MusicAlbum`:

- **Name** ← *first* child track with a non-empty `Album` tag
  (`children.Select(i => i.Album).FirstOrDefault(...)`, L86-91). Folder name is only the initial value.
- **`AlbumArtists`** ← *union* of all child `AlbumArtists`, ordered by frequency
  (`SetAlbumArtistFromSongs`, [L106-126](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/Music/AlbumMetadataService.cs#L106-L126));
  `MusicAlbum.AlbumArtist` = `AlbumArtists.FirstOrDefault()`
  ([`MusicAlbum.cs` L57](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Controller/Entities/Audio/MusicAlbum.cs#L57)).
- **`Artists`** ← union of all child `Artists` (`SetArtistsFromSongs`, L128-146).
- MusicBrainz provider IDs ← majority-vote of child MB tags (`SetProviderIdFromSongs`, L158-180).
- The album's people entries are then written from those unions (`SetPeople`, L195-226).

And the official doc states the contract explicitly
(<https://jellyfin.org/docs/general/server/media/music>):

> "Albums are organized in folders, with **one folder containing one and only one album**. Jellyfin does
> not care how you organize albums together, as long as each album is contained within one folder."

`Playlists/Bussin/` violates that rule — it's one folder containing 92 albums' worth of tracks, so Jellyfin
makes it one album.

**Why artist pages pull in other artists' songs:**

- Artists are generated from per-item *item values* (`ItemValueType.Artist`/`AlbumArtist`), not only from
  folders: `GetAlbumArtists`/`GetAllArtists`
  ([`BaseItemRepository.ByName.cs` L21-36](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Jellyfin.Server.Implementations/Item/BaseItemRepository.ByName.cs#L21-L36)).
- An artist page's items are filtered via `ArtistIds` → `WhereReferencedItem(..., [Artist, AlbumArtist], ...)`
  ([`BaseItemRepository.TranslateQuery.cs` L617-624](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Jellyfin.Server.Implementations/Item/BaseItemRepository.TranslateQuery.cs#L617-L624));
  `MusicArtist.GetTaggedItems` sets `ArtistIds = {Id}` on `Audio`/`MusicAlbum`/`MusicVideo`
  ([`MusicArtist.cs` L77-86](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Controller/Entities/Audio/MusicArtist.cs#L77-L86)).
- Since the pseudo-album's `AlbumArtists`/`Artists` arrays contain **every** contributor, it is linked to
  every one of those artist pages — so e.g. the artist page for a single-track artist still lists the
  "Bussin" album containing 133 other tracks.
- In the track/song DTO, `dto.Album` shows the *correct tag value*, but `dto.AlbumId`/`AlbumPrimaryImageTag`
  point at the pseudo-album entity — so clicking "the album" or viewing its artwork lands on the merged
  playlist album ([`DtoService.cs` L1306-1325](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Dto/DtoService.cs#L1306-L1325);
  `Audio.AlbumEntity => FindParent<MusicAlbum>()`,
  [`Audio.cs` L61](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Controller/Entities/Audio/Audio.cs#L61)).

## 5. Q3 — Compilations / Various Artists

There is **no special "compilation" detection** in current Jellyfin: a repo-wide search finds no
`Various Artists`/compilation logic in `MediaBrowser.*` or `Emby.Server.Implementations`. "Compilation"
is purely emergent: whatever the `ALBUMARTIST`/`TPE2` tag says becomes an album-artist item value
(`audio.AlbumArtists`, `PersonKind.AlbumArtist`); `ALBUMARTIST=Various Artists` just creates/links an
artist literally named "Various Artists". The folder-based `MusicAlbum` + union-of-album-artists model is
what glues unrelated tracks together — the user's ~50 `Various Artists`-tagged tracks are *not* the cause;
they only add a "Various Artists" link.

**Amplifier (this instance):** the "Music" library has MusicBrainz enabled for `MusicAlbum`. The album's
lookup uses `GetLookupInfo` which re-derives the album name from the first child's `Album` tag and carries
the union `AlbumArtists` ([`MusicAlbum.cs` L135-155](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Controller/Entities/Audio/MusicAlbum.cs#L135-L155));
`MusicBrainzAlbumProvider` then searches `"{name}" AND artist:{firstAlbumArtist}`
([`MusicBrainzAlbumProvider.cs` L203-215](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/Plugins/MusicBrainz/MusicBrainzAlbumProvider.cs#L203-L215))
and — on a match — **overwrites `item.AlbumArtists` with the real release's artist credit**
([L287-296](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/Plugins/MusicBrainz/MusicBrainzAlbumProvider.cs#L287-L296)),
plus release/release-group IDs and artwork. So a pseudo-album like "Bussin" (renamed to the first track's
`ALBUM`, majority AA `$uicideboy$`) can be *positively identified as the real album*, complete with
correct-looking art — while containing 133 unrelated tracks.

## 6. Q4 — How `.m3u`/`.m3u8` files are handled

- `Playlist.SupportedExtensions` = `.m3u .m3u8 .pls .wpl .zpl`
  ([`Playlist.cs` L26-32](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Controller/Playlists/Playlist.cs#L26-L32)).
- `PlaylistResolver`
  ([`PlaylistResolver.cs` L22-100](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Library/Resolvers/PlaylistResolver.cs#L22-L100)):
  in `music` (or mixed/`null`) collections, a playlist **file** becomes a `Playlist` item with
  `IsInMixedFolder=true`, `PlaylistMediaType=Audio`. A **directory** becomes a playlist only if named
  `[playlist]`, placed inside the internal `PlaylistsFolder`, or containing `playlist.xml`
  (`PlaylistXmlSaver.DefaultPlaylistFilename`, [`PlaylistXmlSaver.cs` L22](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.LocalMetadata/Savers/PlaylistXmlSaver.cs#L22))
  — so `Playlists/<name>` folders and loose `.m3u` files inside them do **not** turn the folders into playlists.
- `PlaylistItemsProvider` parses the file (PlaylistsNET `M3uContent`, charset via `UtfUnknown` detector)
  and stores each entry as a `LinkedChild` pointing at the already-scanned library item; entries resolve
  relative to the playlist file's directory and must live under a library root
  ([`PlaylistItemsProvider.cs` L98-160, 203-226](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/Playlists/PlaylistItemsProvider.cs#L98-L226)).
- **Effect on metadata: none.** m3u import creates `Playlist` items referencing the tracks; it does not
  change the tracks' `Album`/`Artists`/`AlbumArtists` or album grouping. (Side effects visible in this
  library: 37 root `.m3u` files → 37 playlists, plus ~36 `Untitled.m3u` files → many identically-named
  "Untitled" playlist items, and the m3u references resolve only if paths match under `/media`.)

## 7. Q5 — Multi-artist tag splitting

- Values: ATL joins multi-valued tag fields with `\u001F`; Jellyfin splits on that separator
  (`InternalValueSeparator`, [`AudioFileProber.cs` L31](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L31);
  splits at L212/218/232/238/414). So multiple Vorbis `ARTIST=` comments / multi-frame ID3 values →
  multiple artists.
- `;`, `/`, `feat.`, `&` inside a **single** tag value are **not** split by default. Splitting on custom
  delimiters only happens if the library option `UseCustomTagDelimiters` is enabled
  ([L219-225, 239-245](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L219-L245)),
  using `CustomTagDelimiters` (default `["/", "|", ";", "\\"]`,
  [`LibraryOptions.cs` L11, L125-132](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Model/Configuration/LibraryOptions.cs#L11-L132))
  honouring `DelimiterWhitelist` for names that must not be split
  ([`SplitWithCustomDelimiter` L591-612](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/MediaBrowser.Providers/MediaInfo/AudioFileProber.cs#L591-L612)).
- In this library `UseCustomTagDelimiters` is unset → **off**. Consequences visible in the audit:
  `Mack 10/Ice Cube`, `Snoop Dogg/Kurupt/Warren G/Nate Dogg`, `Yusuf / Cat Stevens`,
  `A Tribe Called Quest feat. Busta Rhymes & Redman` each become **one** artist entity; files with several
  Vorbis `ALBUMARTIST` values (e.g. `Ryo Fukui`, `福居良`, `Ryo Fukui, 福居良` on the same album) become
  several distinct album artists — fragmenting artist pages, but **not** the cause of whole-folder merging.

## 8. Q6 — Relevant settings & supported fixes

- The docs' contract is structural, not configurable: *one folder = one album*
  (<https://jellyfin.org/docs/general/server/media/music>). There is no "prefer embedded metadata /
  ignore folders" toggle for music album grouping.
- **Exclude `Playlists/` from the music library scan** — officially supported via `.ignore`:
  place an **empty** file named `.ignore` inside `/media/Playlists` to exclude that directory and
  everything under it (<https://jellyfin.org/docs/general/server/media/excluding-directory>).
  Implementation: `DotIgnoreIgnoreRule.ShouldIgnore`
  ([`DotIgnoreIgnoreRule.cs`](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Library/DotIgnoreIgnoreRule.cs)),
  consulted at resolve time via `EntityResolutionIgnoreRules`
  ([`LibraryManager.cs` L1007](https://github.com/jellyfin/jellyfin/blob/797999fc9bd49a9f0853916e2933e3ad06173503/Emby.Server.Implementations/Library/LibraryManager.cs#L1007)).
  Note (docs): in 10.11+ a **non-empty** `.ignore` is parsed as gitignore-style patterns — so keep it
  empty, and rescan after adding it. Alternative: gitignore-style `.ignore` at `/media` containing
  `Playlists/` (10.11.x+ only; instance runs 10.11.11 ✓).
  **Caveat:** tracks under `Playlists/` will no longer appear in the library at all; the `.m3u` files
  that reference them still import (entries pointing at non-scanned paths simply resolve to nothing —
  `TryResolvePlaylistItem` requires the file to exist and be under a library root, but the referenced
  item must be found via `FindByPath`; excluded items won't be in the DB, so those playlists will be
  empty). If playlist playback matters, use option (b) or (c) instead.
- **Move the playlist folders out of the music tree** — e.g. `/Users/john/Music/Playlists` outside
  `/media`, and update the `.m3u` paths. Cleanest separation; keeps the m3u files usable if they are
  moved with the audio (or regenerated with new relative paths by `dedup_music.py`).
- **Separate "playlists" media library**: keep the audio in a sibling mount (`/playlists-media`) added
  as its own *music* library — the same folder-per-album problem applies there, so this is only useful
  for isolating the junk albums/artists from the main library, not for browsing them properly.
- **Fix tags for the mismatched `ALBUMARTIST`s** (125 files, incl. ~50 `Various Artists` and a few wrong
  ones like `Zashawn`, `Belinda Carlisle`): even after restructuring, those tags distort album-artist
  unions. Requires a retag + rescan with *Replace all metadata* (ordinary refresh won't overwrite
  `audio.Album/Artists/AlbumArtists`, `AudioFileProber.cs` L342-385).
- **Disable MusicBrainz on `MusicAlbum`/`MusicArtist`** (or accept its matches): prevents pseudo-albums
  from being positively identified as real releases (`MusicBrainzAlbumProvider` overwrites
  `AlbumArtists` on match, §5). Settings → Libraries → music library → metadata downloaders per type.
- **Custom tag delimiters** (`UseCustomTagDelimiters` + `DelimiterWhitelist`) can fix slash/semicolon-joined
  artists (`Mack 10/Ice Cube`) — but only with a whitelist containing names like `AC/DC`,
  `Crosby, Stills, Nash & Young`... splitting is per-char (`/`,`|`,`;`,`\`) so `feat.`/`&` can't be
  configured as delimiters anyway.
- `.nomedia` is a *different* mechanism — it's Android/Kodi-style and **not** documented for Jellyfin
  music libraries; use `.ignore`.

## 9. Likely root cause(s), ranked

1. **Folder-per-album grouping** (primary): `Playlists/<name>/` is one folder containing audio files →
   one `MusicAlbum` (`MusicAlbumResolver` L57-82 + `ContainsMusic` L125-180). Its displayed name is the
   first child's `ALBUM` tag (`AlbumMetadataService` L86-91) and its artists/album-artists are the union
   of all children (L106-146). This alone fully explains "entire playlist attributed to a single album".
2. **Folder-per-artist grouping**: `Playlists/` itself → `MusicArtist` "Playlists" (MusicArtistResolver
   L112-119), so the pseudo-albums are parented under a bogus artist too.
3. **Union-of-artists linking**: the pseudo-album is `WhereReferencedItem`-linked to every contributing
   artist (`TranslateQuery` L617-624), so every artist page lists it → "artist pulls in other artists".
4. **MusicBrainz identification** (amplifier): pseudo-album is looked up as `"{firstChildAlbum}" AND
   artist:{majorityAA}` and can be matched to the real release, overwriting `AlbumArtists` with the real
   artist credit and attaching artwork/IDs — cementing single-artist attribution.
5. **(Contributing, not causal)** wrong/Various-Artists `ALBUMARTIST` tags on 125 files and multi-value
   artist tags add extra wrong artist links; `Untitled.m3u` files create duplicate playlist items but do
   not affect album/artist metadata.
